## 0. 先说结论

设计系统的**上层建筑是正确的**：token 单一来源、`--ui-hue` 从壁纸派生、`ui-buttons.css` 作为唯一按钮层、`app-shell.css` 统一四个分区页头。这些在实测中确实生效。

问题全部集中在**执行层**：三条链路各自断裂。

1. **深色主题下 Element 主按钮文字不可见**（P0，白底白字）
2. **选中态完全不可见**（P0，选中与未选中渲染完全一致）
3. **`mobile-refactor.css` 用 294 个 `!important` 架空了按钮层**（P1，同一 `.btn` 在两个页面是两种尺寸）

文字对比度实测全部合格（最低 9.65:1），排版层是健康的。所以这不是"设计不好看"的问题，是**系统没有真正连通**。

## 1. P0 — 阻断级缺陷

### 1.1 深色模式下 Element 主按钮：白底白字，文字不可见

**实测证据**（`admin.html`，`data-theme="dark"`，1440×900）

```
el-button--primary  "上传文件"   bg=rgb(255,255,255)  color=rgb(255,255,255)
el-button--primary  "创建"       bg=rgb(255,255,255)  color=rgb(255,255,255)
el-button--primary  "移动到所选目录" bg=rgb(255,255,255)  color=rgb(255,255,255)
```

三个主按钮的 `background-color` 与 `color` **完全相同**。截图里表现为三个白色空胶囊，上面没有字。

**根因**（`theme.css`）

- 浅色档 255-259 行：`background` + `border-color` + **`color: var(--ui-brand-ink)`** ← 三件套齐全
- 深色档 283-286 行：`background` + `border-color`，**缺 `color`** ← 少了这一行
- 深色档 767-770 行：同样的遗漏，同样缺 `color`

深色模式下 `--ui-brand` 求值为 `#ffffff`（`--ui-brand-dark`），于是 `background` 变成纯白；`color` 没有被覆盖，沿用 Element 默认的 `#fff`。白压白。

浅色模式实测正常（`bg=rgb(0,0,0)` / `color=rgb(252,252,252)`），因为那条规则写全了。

**修复**：补两处 `color`。

```css
html[data-theme="dark"] .el-button--primary {
  background: var(--ui-brand) !important;
  border-color: transparent !important;
  color: var(--ui-brand-ink) !important;   /* ← 补这一行 */
}
```

`--ui-brand-ink` 在深色档求值为 `hsl(0 0% 7.1%)`（近黑），压在白底上是 20.4:1。两处（283、767）都要补。

**这一条不需要任何设计判断，是纯粹的遗漏。建议立刻修。**

### 1.2 选中态不可见：选中与未选中渲染完全一致

**实测证据**（`index.html`，深色，展开"选择已有目录"与"图片压缩与转换"）

| 元素 | 选中 | background | border | color | font-weight |
|---|---|---|---|---|---|
| 根目录 | ✅ | `rgb(36,36,36)` | `rgb(69,69,69)` | `rgb(237,237,237)` | 400 |
| 原图 | ❌ | `rgb(36,36,36)` | `rgb(69,69,69)` | `rgb(237,237,237)` | 400 |
| 压缩转换 | ❌ | `rgb(36,36,36)` | `rgb(69,69,69)` | `rgb(237,237,237)` | 400 |
| 每次询问 | ✅ | `rgb(36,36,36)` | `rgb(69,69,69)` | `rgb(237,237,237)` | 400 |

**四个值的每一项都相同。**用户无法判断当前选的是哪一项。

**根因**：`index.html` 用 `:class="{ 'is-selected': ... }"` + `:aria-pressed` 标记选中（78-79、109-115、182-189、320-323 行，共 4 组控件），但：

- `ui-buttons.css:221` 只在 `.segmented > .btn[aria-pressed="true"]` 下写选中态，而这四组都不在 `.segmented` 里
- 全站没有任何 `.btn.is-selected` 规则

`workbench.css` 确实有 `.is-selected` 规则（99、170、422 行），但只覆盖 `.upload-storage-option` / `.upload-result-row` / `.file-tile`，不覆盖通用 `.btn`。

**影响面**：存储目标、目录选择、图片处理方式、复制链接格式 —— 四个决定上传行为的控件，用户都看不见当前值。

**修复**：在 `ui-buttons.css` 加一条通用规则，与 `.segmented` 那组共用同一套取值。

```css
/* 独立按钮的选中态。此前的选中样式只写在 .segmented 内部，
   页面里直接用 .btn + is-selected 的控件（存储目标、目录、图片处理、
   链接格式）因此完全没有视觉反馈 —— 四个控件看不出当前值。 */
.btn.is-selected,
.btn[aria-pressed="true"] {
  background: var(--ui-brand-soft);
  border-color: var(--ui-brand);
  color: var(--ui-brand);
  font-weight: 600;
}
.btn.is-selected:hover,
.btn[aria-pressed="true"]:hover {
  background: color-mix(in srgb, var(--ui-brand) 16%, transparent);
}
```

注意 `--ui-brand-soft` 在纯黑白主题下是 `color-mix(#fff 10%, transparent)`，配 `--ui-brand: #fff` 文字，对比度约 1.05:1 —— **在默认无壁纸的黑白主题下仍然不可见**。

所以这条要落在 `--ui-brand` 之上，补一个边框与字重变化：

```css
.btn.is-selected,
.btn[aria-pressed="true"] {
  border-color: var(--ui-brand);
  color: var(--ui-ink);            /* 文字用 ink，不用 brand */
  background: color-mix(in srgb, var(--ui-brand) 14%, var(--ui-surface-raised));
  font-weight: 600;
}
```

深色档 `--ui-surface-raised` 是 `hsl(0 0% 14%)`，混 14% 白后约 `rgb(50,50,50)`，配 `--ui-ink`（237）是 12.6:1。选中的辨识来自**边框 + 字重 + 底色**三重差异，任何壁纸色下都成立。

### 2.1 `mobile-refactor.css` 用 294 个 `!important` 架空了按钮层

**实测证据**：同一个 `.btn.btn-primary` 在两个页面

| 文件:行 | 规则 | 覆盖了谁 |

| `mobile-refactor.css:578-583` | `.btn { padding: 8px 10px !important; font-size: 0.8rem !important }` | 上一条 |
| `mobile-refactor.css:329` | `.form-input { border-radius: 11px !important }` | 11px 全站独有 |

**修复**（按顺序，每步可独立验证）：

1. 删除 `mobile-refactor.css` 里所有针对 `.btn` / `.form-input` / `.toolbar` / `.card` / `.stat-badge` / `.batch-bar` 的规则。按钮的尺寸与 44px 触摸下限 `ui-buttons.css:254-275` 已经做了，重复覆盖只会打架。

3. 剩余的 `--nav-height` / `body` 下内边距 / `.el-message` 视口修正 / `prefers-reduced-motion` 块，归并到各自的归属文件（页头归 `app-shell.css`，触摸归 `ui-buttons.css`）。
4. 目标：`mobile-refactor.css` 从 1092 行降到 200 行以内，`!important` 从 294 降到个位数。

**验收**：390px 下 `.btn` 的 `padding` 在 `index.html` 与 `gallery.html` 上应完全相同。

### 2.3 文件卡片操作栏溢出，"预览/复制"被挤成两行

**实测证据**（`admin.html`，1440px，`.file-tile` 宽 209px）

}
.kv-files .file-tile-actions {

### 3.4 顶栏半透明在滚动时压出内容

**实测**：`backdrop-filter: blur(14px) saturate(1.15)`，`background: color(srgb .11 .11 .11 / .93)`。

截图可见：向下滚动时，上传页的输入框轮廓、图库的卡片边缘会从顶栏半透明的部分透出来。0.93 的不透明度不足以压住 1px 的边框线。

**这不算 bug** —— `app-shell.css:60-66` 的注释说得很清楚，这是让"卡片透明度"滑杆对顶栏生效的有意设计。但 **0.93 是默认值，用户没调过**。默认状态下顶栏应该是不透明的实心表面，只有用户主动降低透明度时才允许透出。

**修复**：把默认定在 1.0，或者在顶栏自己的背景上再叠一层 `var(--ui-surface)` 保证最低不透明度。这一条需要你确认是不是有意为之 —— 如果是设计意图，就跳过。

```

`em` 是相对**父元素**的，所以同一段文字的实际字号取决于它被放在哪 —— 这不是风格问题，是行为问题。`.upload-hint` 是 `0.9em`（`index.css:257`），窄屏被改成 `0.82em !important`（`mobile-refactor.css:161`），而旁边的 `.upload-muted` 是 `.8125rem`（固定 13px）。**同一张卡片里三个同级辅助文字，三种实际字号。**

`font-weight` 还有 `650` 与 `800` 两个值：可变字体（Manrope/Sora）支持，系统回退字体不支持，无字体加载时 `650` 会吸附到 700，层级塌掉。而且 `Manrope` / `Sora` 在 HTML 里**根本没有 `<link>` 引入**（`theme.css:540-541` 定义了 token 却没人加载字体），于是所有 `650` 在当前部署里都已经吸附成 700 了。

**建议**（这一条工作量大，建议单独排期）：

1. 先定一份 6 级固定 rem 刻度：`--text-xs: .75rem` / `-sm: .8125rem` / `-base: .875rem` / `-md: .9375rem` / `-lg: 1.125rem` / `-xl: 1.5rem`
2. 用 codemod 把 `em` 全部换算成 `rem`（`em` 在 UI 里几乎没有正确用法）
3. 把 `650` / `800` 降到 `600` / `700`
4. 决定 Manrope 到底加不加载；不加载就从 token 里删掉

**这一条不影响功能，可以最后做。** 但 `em` → `rem` 的换算有实际收益：现在改一个父容器的字号会连带改掉里面所有 `em` 文字。

## 6. 顺带发现的两个非样式问题

### 6.1 "文件"导航在根路径下错误高亮"上传"

`app-shell.css:115-119` 用 `a[aria-current]` 标记当前分区。实测根路径 `/`：

```
上传 -> ./             ← 高亮（正确）
文件 -> ./admin.html
图库 -> ./gallery.html
视频 -> ./video.html
```

但 `/` 同时是上传页**和**文件工作台所在页（`/admin` 也是），`aria-current` 只按 URL 精确匹配，于是从文件页回到 `/` 时高亮会跳回"上传"。这是 `aria-current` 用法本身的局限，不是样式问题，但用户会感知为"导航乱跳"。

建议改用路径前缀匹配，或给两个页面显式传不同的 `aria-current`。

### 6.2 `admin-imgtc.css` 已不存在但仍被三处引用

```

仓库里 `ls *.css` 没有这个文件。`app-shell.css:51-59` 的六个 `!important`（padding / background / border / border-bottom / border-radius / box-shadow）全部是为了压这个已删除的文件。清理掉之后那六个 `!important` 可以去掉。
